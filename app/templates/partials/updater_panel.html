Two things here are load-bearing and easy to undo by accident: 1. The poll lives on #updater-panel ITSELF, which is also hx-swap's target. htmx re-initialises the replacement, so the loop continues across swaps. Putting it on an inner element instead would work until the first swap replaced that element mid-flight. 2. data-htmx-no-error="1" sits on the polling element because base.html's ISS-007 handler reads evt.detail.elt — the element that TRIGGERED the request. Without it, every failed poll during the app's own restart would overwrite the panel with a "couldn't load" pill, destroying the poll and stranding the operator on an error ~20 times over a 30-60s restart. Confirmation uses htmx's own hx-confirm rather than the repo's data-confirm dispatcher: data-confirm listens for the native submit event, and racing htmx's own submit handling for the same event is a coin flip. hx-confirm is evaluated by htmx before it issues the request.
